# Integration prompt

Use after the independent components exist. Dev coordinates, each owner edits their sector. Do not use this as permission for a model to overwrite the whole repository.

~~~text
Integrate the current SteadyHand repository without rewriting working sectors. Read AGENTS.md, plan.md, architecture, contracts, testing, and actual module READMEs. Inspect real exports/configuration and identify the smallest vertical slice currently broken.

Trace these paths separately:
1. Popup enable -> worker injection -> content -> pure engine -> overlay -> one eligible action.
2. Popup settings -> validated revision -> content cancel/reset/apply.
3. Mock service -> authenticated worker WS -> source/quality -> UI.
4. Real sensor -> MCU queue -> tested bridge adapter -> analysis -> derived frame.
5. Confirmed eligible selection -> optional bounded cue -> pulse/settling blanking.

Prefer one reproduction and one boundary fix. List an interface mismatch as producer, consumer, expected shape, actual shape, and owner. Do not duplicate filters, relax validation to accept corrupt data, or hide failures behind a synthetic success state.

Verify packaged extension assets, active-tab enable path, UI mounts, dependency imports, worker restart, stale sensor, cleanup, keyboard/native fallback, and at-most-once action. Sensor/network absence must preserve local assistance.

Do not claim end-to-end latency by subtracting unrelated clocks. Do not claim motor execution from acknowledgment alone. Do not label replay live. Do not silently expand permissions or add cloud dependencies.

After each fix, run the smallest meaningful check and re-run the affected vertical slice. Report owner-scoped edits, actual commands/results, remaining blockers, supported compatibility, and exact demo launch sequence. If edits cross ownership, present the patch to that owner for coordinated application.
~~~
