# SteadyHand V2: Adaptive Forms with Gemini

## Overview

**Adaptive Forms with Gemini** is an AI-powered presentation adaptation feature built into SteadyHand V2 to assist individuals with hand tremors when navigating dense, compact, or confusing web forms.

While SteadyHand's core engine stabilizes the mouse pointer (using a client-side 1-Euro adaptive filter) and provides cancellable dwell selection, Adaptive Forms addresses the layout challenge: restructuring multi-column, tightly spaced form inputs into an accessible single-column flow with enlarged touch/click footprints and clear section headings generated by Gemini.

---

## Nonnegotiable Architectural Invariants

1. **Reversible Presentation Only**:
   - The original native DOM elements remain in their exact parentage and sequence.
   - Elements are **never** removed, replaced, or cloned.
   - All native event listeners, constraints (`required`, `pattern`), form `action`, and native submit handlers are 100% preserved.
2. **Strict Privacy by Design**:
   - Only document-local synthetic aliases (`field-1`, `field-2`) and generic labels are sent for layout planning.
   - User-entered values (`input.value`, `checkbox.checked`), passwords, payment fields, hidden tokens, page HTML, and URLs are **never** extracted or transmitted.
   - Gemini API calls enforce `store=false`.
3. **Synchronous Layout Transition Guard**:
   - Applying or restoring an adaptive layout immediately halts in-progress dwell and clears assisted-click arming.
   - The engine rescans target boundaries and increments `geometryRevision` to ensure no misclicks occur as layout dimensions change.
4. **Independent Pointer Loop**:
   - Cursor stabilization and dwell timing execute completely on the client side. They do not wait for network requests or cloud AI responses.
5. **Native Submission Pathway**:
   - Submit buttons (`type="submit"`) remain native-only interactions. The extension never synthesizes artificial click cascades or programmatic `form.submit()`.

## System Architecture

```
User Browser (Chrome MV3)
├── Content Script
│   ├── detector.ts          ── Scans DOM for supported, non-sensitive <form>
│   ├── extractor.ts         ── Generates aliases (field-1) & sanitizes metadata
│   ├── preview.ts           ── Renders read-only layout preview modal
│   ├── renderer.ts          ── Injects CSS classes & section titles (textContent only)
│   ├── mutationJournal.ts   ── Tracks injected classes/nodes for clean reversal
│   └── controller.ts        ── Coordinates lifecycle & executes dwell cancel guard
└── Background Worker
    └── adaptiveFormsClient.ts ── Communicates with local FastAPI bridge
            │
            ▼ (HTTP POST /v1/adaptive-forms/plan)
Local FastAPI Bridge (127.0.0.1:8765)
├── security.py              ── Pairing token auth, rate limits (5/min), concurrency (2)
├── planner.py               ── Async google-genai client (gemini-3.8-flash) + heuristic fallback
└── models.py                ── Strict Pydantic models enforcing schema & DOM order
            │
            ▼ (HTTPS Structured Output)
Google Gemini API (gemini-3.8-flash)
```

## Practice Fixture

SteadyHand V2 includes a dedicated practice form fixture located at:
`apps/fixtures/adaptive-forms.html` (served via local HTTP or direct file URL).

### Fixture Controls Included:
- **Participant Nickname**: Text input (`required`)
- **Special Interests**: Textarea
- **Workshop Track**: Atomic radio group (`Drawing`, `Gardening`, `Woodworking`)
- **Accommodations**: Checkboxes (`Large Print Materials`, `Audio Recording`)
- **Preferred Time Slot**: Native `<select>` dropdown
- **Native Submit Button**: Includes a local counter tracking actual native submissions.

## Step-by-Step Manual Verification Checklist

### 1. Start the Bridge Service
Run the bridge service in mock or hardware mode:
```powershell
# In PowerShell:
.\scripts\run-mock.ps1
# Or direct Python:
python -m steadyhand_bridge --mode mock --port 8765
```
*Verify: Bridge logs indicate `/v1/adaptive-forms/plan` and `/v1/stream` are active on `127.0.0.1:8765`.*

### 2. Build and Load Extension
```powershell
npm run build --prefix apps/extension
```
1. Open Google Chrome and navigate to `chrome://extensions/`.
2. Enable **Developer mode** (top right toggle).
3. Click **Load unpacked** and select `c:\Dedee\SteadyHand_Extension_Full_Plan\apps\extension\dist`.

### 3. Open Practice Fixture
Open `apps/fixtures/adaptive-forms.html` in Chrome:
```
file:///C:/Dedee/SteadyHand_Extension_Full_Plan/apps/fixtures/adaptive-forms.html
```

### 4. Enable SteadyHand Assistance
1. Click the SteadyHand icon in the Chrome extension toolbar.
2. Click **"Enable on this page"**.
3. Move the cursor over inputs: observe the stabilized virtual pointer and dwell rings.

### 5. Adapt Form with Gemini
1. Open the popup again: observe the **"✨ Adapt Form with Gemini"** card.
2. The badge should display **"Form Ready (5 fields)"**.
3. Click **"Adapt Form"**.
4. The background sends the sanitized metadata to the bridge, which contacts Gemini (or deterministic planner in mock mode).
5. A floating **"Adaptive Layout Preview"** modal appears over the webpage showing proposed section groupings.
6. Click **"Apply Adaptive Layout"**.

### 6. Verify Adaptive Layout Invariants
- **Visual Presentation**: The form adapts to a single-column card layout with bold section headings (`Your Profile`, `Workshop Selection`, `Session Details`).
- **Enlarged Targets**: Inputs and radio items expand to large, easy-to-click hitboxes (minimum 44px).
- **Data Preservation**: Type a nickname (e.g. `Sam`) and select a radio button before or after adapting; confirm the text and selection remain intact.
- **Assisted Dwell**: Hover over inputs; dwell-focus activates smoothly.

### 7. Verify Native Submission
1. Click the primary **"Submit Registration"** button.
2. Confirm the **"Native Submissions Dispatched"** counter increments by 1.
3. Confirm that dwell never accidentally triggers submission.

### 8. Verify 100% Reversibility (Restore Original)
1. Open the popup and click **"Restore Original"**.
2. Confirm the form instantly snaps back to its original layout.
3. Confirm that typed text (`Sam`) and chosen radio buttons are **not lost**.
